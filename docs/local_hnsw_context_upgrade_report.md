# 加拿大法律 RAG 本机升级与评测报告

日期：2026-11-03
范围：仅本机代码、PostgreSQL 与 pgvector；未迁移、未部署、未执行整库上下文向量回填。

## 1. 本次升级结果

本次把“LLM 抽关键词后单轮检索”改造成有界的多轮证据研究流程，并完成以下工程改造：

1. 删除已失效的中国民事审判服务、测试、脚本和隔离备份，只保留加拿大/Ontario 工作流。
2. 删除旧近似索引模块、产物、配置、接口与依赖，统一到本地 pgvector HNSW。
3. 删除 512/64 固定滑窗切分，使用 `legal-context-v2` 结构化分块。
4. 原文和上下文索引分离：原文负责引用，上下文前缀负责召回。
5. 增加高置信别名、唯一主体消歧和 unresolved 标记，避免对“该公司/其”强行猜测。
6. 离线抽取实体、提及和证据化关系；在线对当前案件抽取/链接实体，并进行一至三跳图谱扩展。
7. 多轮检索按争点并行执行，基于证据矩阵的缺口构造下一轮查询，受轮数、超时和边际收益约束。
8. 页面实时展示阶段、单个查询开始/完成、命中、缺口、下一动作和终止原因，并支持暂停、继续、终止和补充查询。
9. 外部文本只作为数据，不作为指令；陈旧向量通过 `content_hash` 校验被排除。

## 2. 新版主流程

用户输入（可中文） → 确认加拿大法域 → 事实/争点/实体提取 → 首轮法规与案例查询并行执行 → 关键词/HNSW/图谱候选融合 → 证据回取与重排 → 逐争点覆盖评估 → 缺口驱动的第二轮精确查询 → 有界停止 → 结构化结论与引用。

多跳不是让模型在检索结果上自由联想。离线阶段把原始文档中的法规、条文、案件、法院、问题、救济、量刑因素和引用关系链接到 canonical ID；在线阶段把当前案情实体链接到相同 ID，再沿有来源证据的关系边扩展并回取原文块。最终结论仍必须由原始证据支持。

## 4. 相对旧流程的预期与已测提升

已客观测得的提升：隔离样本语义检索 Recall@10 为 1.00；相对同样本精确余弦检索，平均延迟从 21.611 ms 降到 6.318 ms，降低 70.8%，吞吐意义上的加速约 3.42 倍。

结构化分块、多轮检索和图谱多跳的业务提升尚不能用主观百分比替代正式评测。当前可确认的结构性改进是：

- 从一次查询变为“拆分—检索—评估—补查”的最多五轮闭环；
- 从孤立文本块变为“文档/章节/段落/实体上下文 + 原文”；
- 从隐式关系猜测变为带来源 chunk 的实体关系路径；
- 从整轮等待变为查询完成即推送；
- 从可能的大表退化扫描变为无有效 HNSW 就显式失败。

待全量索引完成后，使用固定评测集同时运行旧单轮基线与新版流程，才能给出争点覆盖率、nDCG、citation precision、authority validity 和 hallucination rate 的可信提升幅度。

当前全量本机 HNSW 构建已启动。构建期间索引未 valid/ready，应用不会使用它。下一步顺序：

5. 本地整体效果通过后，再由用户另行安排迁移。
